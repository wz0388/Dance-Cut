# DanceCut —— 舞蹈片段自动识别与切片

## 一、怎么运行

**双击 `DanceCut` 文件夹里的 `DanceCut.exe` 就行。**
不需要装 Python，也不需要装 ffmpeg（都打包在里面了）。

> 重要：`DanceCut.exe` 必须和同目录的 `_internal` 文件夹放在一起，**整个 `DanceCut` 文件夹是一个整体**，
> 不要只把 exe 单独拷走。要搬到别的电脑，请整个文件夹一起拷，或用 `DanceCut_portable.zip` 解压。

启动大约 1~3 秒。

## 二、两种模式

界面最上面有两个选项：

### ① 批量处理文件夹（默认，推荐）

选一个**文件夹**，程序会把里面所有视频逐个处理，**每个视频在它自己旁边新建一个和视频同名的专用文件夹**放结果。

```
D:\我的视频\
├── 第一期.mp4
├── 第二期.mp4
├── 第三期.mp4
├── 第一期\            ← 自动新建
│   ├── clips\dance_01.mp4 …
│   ├── dance_result.csv
│   └── run_summary.json
├── 第二期\            ← 自动新建
└── 第三期\            ← 自动新建
└── batch_summary.csv  ← 批量汇总（每个视频出了几段）
```

勾选项：

| 选项 | 说明 |
|---|---|
| 包含子文件夹 | 勾上后连子文件夹里的视频一起处理 |
| 跳过已处理过的视频 | 默认勾上。已经跑过的视频（有 `run_summary.json`）不再重复跑；想重跑就取消勾选 |

「输出根目录」留空 = 每个视频在自己旁边建同名文件夹；想集中放到一个地方，就选个目录，
结果会变成 `<该目录>\<视频名>\`。

### ② 单个视频文件

只处理一个视频，输出到指定的 `dance_out` 目录。

### 参数说明

| 参数 | 默认 | 含义 |
|---|---|---|
| 采样间隔(秒) | 3 | 每隔多少秒抽一帧做骨骼判定。越小越准、越慢 |
| 中间可停留(秒) | 27 | 两段舞蹈之间停顿不超过这个时间，就当同一段，不拆开 |
| 最短舞蹈(秒) | 24 | 舞蹈本身短于这个时间的，整段不要 |
| **舞蹈内门槛** | 0.075 | **放松 A**：已经处于舞蹈状态时，运动量门槛从 0.09 降到这个值 |
| **露腿门槛** | 0.070 | **放松 B**：画面露出腿（半身以下到全身）时再降一档，更容易判为跳舞 |
| 并行进程 | CPU核数-1 | 骨骼识别的并行度。**跑不动就改成 1**（单进程最省内存、最稳） |

勾选项（第二行右侧）：

| 选项 | 默认 | 说明 |
|---|---|---|
| **输出骨骼画面** | 勾上 | 把每张采样图叠加人体骨骼 + 判定信息，存到 `<视频名>\skeleton\` |
| **只输出舞蹈帧** | 不勾 | 只给被判为舞蹈的帧出骨骼图，省空间（几千张 → 几百张） |
| **文件名带原片时间** | 勾上 | 片段名变成 `dance_01_005239-005854.mp4`，一眼看出取自原片哪一段 |
| **画面左上角叠时间码** | 不勾 | 视频画面上直接烧录 `SRC 00:52:39 - 00:58:54  #1` |

想少一点误判就把两个门槛往上调（调到 0.09 就等于关掉对应放松）；想多抓一点舞蹈就往下调。

## 片段取自原片哪里？（标注）

切出来的每段都会标明它在原片里的时间区间，三个地方都能查：

**① 文件名**
```
dance_01_005239-005854.mp4     ← 取自原片 00:52:39 - 00:58:54
dance_02_010551-010642.mp4     ← 取自原片 01:05:51 - 01:06:42
```

**② `clips\片段来源.txt`**（人可读清单）
```
源视频：F:/AI/input/xxx.mp4
共 2 段，合计 7.0 分钟

序号   文件                             取自原片                  时长
1    dance_01_005239-005854.mp4     00:52:39 - 00:58:54     375.0s
2    dance_02_010551-010642.mp4     01:05:51 - 01:06:42      51.0s

合集内位置对照：
   dance_01_005239-005854.mp4     合集 00:00:00 - 00:06:15
   dance_02_010551-010642.mp4     合集 00:06:15 - 00:07:06
```

**③ `clips\concat.txt`**（拼接清单，注释里带区间；ffmpeg 会自动忽略 `#` 开头的行）
```
# 源视频：F:/AI/input/xxx.mp4
#  1  dance_01_005239-005854.mp4   原片 00:52:39 - 00:58:54  (375.0s)
#  2  dance_02_010551-010642.mp4   原片 01:05:51 - 01:06:42  (51.0s)

file 'dance_01_005239-005854.mp4'
file 'dance_02_010551-010642.mp4'
```

**④ 画面烧录时间码（可选）**：勾上「画面左上角叠时间码」后，每个片段画面上会常驻
`SRC 00:52:39 - 00:58:54  #1`，直接看视频就知道来源。用系统字体（arial），
找不到字体时会自动跳过（不影响切片，文件名和清单仍有标注）。

另外 `dance_clips.csv` 里也有 `file` / `src_start` / `src_end` / `start_s` / `end_s` 等列，方便程序处理。

## 输出骨骼画面怎么用

勾上「输出骨骼画面」后，每个视频目录里会多一个 `skeleton\` 文件夹：

```
<视频名>/skeleton/
├── s00123_t00369.jpg        帧序号 + 时刻；文件名带 _D 的是判定为舞蹈的帧
├── s00456_t01368_D.jpg
├── _总览.jpg                自动拼的总览图（20 张，快速扫一眼）
└── _说明.txt                图上各个标记和图例的说明
```

图上画了：**人体骨架（33 点）**、腿部的膝/踝（露出腿时加粗高亮）、双手骨骼（21 点，只画判定为舞蹈的帧），
以及左上角的判定信息面板（`t / ST 站立 / LEG 露腿 / HND 手部状态 / m3 运动量 / thr 该帧门槛 / near 是否在舞蹈邻域 / 最终判定 / rl 放松档位`）。

> 图上的文字用英文缩写，因为 OpenCV 画不了中文；对照关系写在 `_说明.txt` 里。
> 骨骼图会占空间：4 小时视频、3 秒采样约 4800 张，和 `frames\` 差不多大。
> 只想核对判定结果的话，勾上「只输出舞蹈帧」能省 90% 空间。

### 大概要跑多久

4 小时的视频、采样间隔 3 秒、6 个并行进程，大约 **4~8 分钟**（取决于 CPU）。
批量模式下进度条是按「第几个视频 + 该视频内的进度」折算的，日志里每个阶段都会打「[xx 用时 N 秒]」。

## 三、每个视频的专用文件夹里有什么

```
<视频名>/
├── frames/                    每 N 秒抽出来的截图
├── skeleton/                  骨骼画面（勾选后才有）
├── clips/
│   ├── dance_01_005239-005854.mp4 …   切好的舞蹈片段（文件名带原片时间区间）
│   ├── ALL_DANCE.mp4          所有片段合成的合集
│   ├── concat.txt             拼接清单（注释里带每段的原片区间）
│   └── 片段来源.txt            人可读的来源对照表 + 合集内位置对照
├── dance_result.csv           逐帧判定表（是否站立 / 手部状态 / 各项指标）
├── dance_clips.csv            片段清单（文件名、原片起止、时长）
├── dance_blocks_analysis.csv  合并与过滤过程（哪个块被丢弃、为什么）
└── run_summary.json           本次运行汇总
```

`dance_result.csv` 里的关键列：

- `body_state` / `is_standing` —— 人体骨骼是否判定为站立
- `hand_state` / `hand_pose` / `hand_move` / `hand_dance` —— 手部骨骼状态
- `m_roll3` / `active` —— 持续运动量
- `dance` —— 最终是否舞蹈帧
- `clip_id` / `clip_role` —— 属于第几段、该帧在片段里的角色（dance / bridge / pre_pad）

## 四、判定规则（写在程序里的）

### 基础三条（同时满足才算舞蹈帧）

1. **站立取景**：肩中点画面高度 `sh_y < 0.44` 且肩宽 `sh_w < 0.27`，**或者 露出腿**
2. **手部骨骼＝舞蹈**：手腕高于/接近肩（`up > -0.40`），或手臂外展（`lat > 0.45`），
   或屈肘抬起（肘角 < 115° 且 `up > -0.55`），且手部骨骼可见度 > 0.5；
   或者手腕骨骼 3 秒内位移 > 0.45 倍躯干长
3. **持续运动**：画面帧差运动量的 3 帧滚动均值 > 0.09

> **第 ① 条为什么要加"或者露出腿"**：只靠肩部判据时，**离镜头近的直播**（例如抖音竖屏录制）
> 肩宽会超过 0.27，导致整段视频一帧都判不出"站立"（实测某 46 分钟视频只有 14/917 帧通过，
> 结果 0 片段）。而同一个视频里有 **53% 的帧能看到腿**、其中 83% 运动量超过 0.09 —— 
> 所以「露出腿」必须能独立满足第 ① 条。

### 两条"更容易判为跳舞"的放松

为避免漏掉"动作幅度小而确实在跳"的片段，在上面三条之上加两条放松。两条都需要一个
**高置信锚点**（基础三条全过、且运动量 > 0.13）来解锁，否则坐姿聊天会被误判。

**放松 A —— 当处于舞蹈状态时降低运动量门槛**
高置信锚点前后各 2 个采样（±6 秒）之内，运动量门槛从 0.09 降到 **0.075**，
同时手部姿态判据放宽（`up > -0.58` / `lat > 0.34` / 肘角 < 132°，可见度 > 0.40）。
效果：舞蹈中间安静下来的那几秒不会被切断。

**放松 B —— 露出腿（半身以下到全身）时更容易判为跳舞**
"露出腿"用骨骼关键点的可见度判断：**膝关节可见度 > 0.35 或踝关节可见度 > 0.20**
（左右取较小值，即两条腿都要看得见）。在紧机位下髋/膝/踝会被 MediaPipe 外推到画面之外，
可见度≈0，所以这个指标能可靠区分"桌面近景"和"拉开到能看到腿"。

命中"露腿"时：
- 站立判据放宽（肩宽条件放到 `sh_w < 0.32`；在锚点邻域内则直接视为站立）
- 运动量门槛再降到 **0.070**
- 手部姿态判据同上放宽

> **重要更正：`露腿` ≠ `站立`。** 实测发现主播坐在矮沙发上时腿一样会入镜，
> 所以不能只靠腿部可见度就认定站着。因此所有放松帧还额外要求**肩膀位置够高**
> （`sh_y < 0.42`，即站姿取景）—— 这一条把"坐矮沙发露腿"的情况挡在了外面。
> 另外把"腿可见"当独立判据直接放行，会让坐姿区多出十几个假片段
> （坐姿画面里约 12% 的帧会被误报为"腿可见"），所以两条放松都以"锚点邻域"为边界。

### 切片规则

- 片段起点取**上一张非舞蹈采样图**的时间点，终点取下一张 → 保证舞蹈首尾不被切掉
- 中间停留 ≤ 27 秒视为同一段
- 舞蹈本身 < 24 秒整段跳过
- 保持原始画面，不做任何裁切

## 五、常见问题

**Q: 双击没反应 / 闪一下就没了**
看 exe 同目录的 `logs\stdout.log`，里面会有报错。

**Q: 视频文件名带中文会不会有问题**
不会。程序已经专门处理过中文/非 ASCII 路径（OpenCV 默认读不了中文路径，这里绕过了）。
自检里也有这一项。

**Q: Windows 提示"已保护你的电脑"**
exe 没有数字签名，点「更多信息」→「仍要运行」即可。

**Q: 杀毒软件报警**
PyInstaller 打包的程序偶尔会被误报，加白名单即可。

**Q: 日志停在"人体骨骼识别"很久**
几小时的视频本来就要跑几分钟。日志每 25/100 帧会打一次进度，看数字在不在涨。
如果一直不动，把「并行进程」改成 1 再试。

**Q: 想中途停止**
点「停止」，会在当前帧停下来。

**Q: 检测到的片段不对**
先看 `dance_blocks_analysis.csv` 确认是不是被"最短舞蹈"过滤掉了（`kept` 列）。
如果是漏检/误检，属于判定阈值问题，需要调规则而不是调切片参数。

**Q: 批量跑完想补跑某几个视频**
删掉那几个视频对应的专用文件夹，再跑一次批量即可（其余会被自动跳过）。

## 六、命令行用法（可选）

```
:: 单个视频
DanceCut\DanceCut.exe --cli --video 视频.mp4 --out 输出目录 ^
    --step 3 --bridge 27 --min-dance 24 --workers 6
:: 可选：--skeleton 输出骨骼画面   --skeleton-only-dance 只输出舞蹈帧
::       --burn-ts 画面叠时间码    --no-ts-name 文件名不带时间

:: 批量（每个视频各建一个同名文件夹）
DanceCut\DanceCut.exe --cli --batch D:\我的视频 ^
    --step 3 --bridge 27 --min-dance 24 --workers 6
:: 可选：--recursive 含子文件夹    --no-skip 不跳过已处理的

:: 自检（验证 ffmpeg / 模型 / 推理链路 / 中文路径 / 批量逻辑）
DanceCut\DanceCut.exe --self-test
```

自检结果写在 `DanceCut\logs\selftest_result.txt`。

### 为什么是文件夹而不是单个 exe

试过 `--onefile`（真正的单文件 exe，142MB），但这个程序内含 87MB 的 ffmpeg，
**每次启动都要把 140MB 解包到临时目录，实测要 2 分 50 秒**，而且还会有多个子进程各自再解包一遍。
改成文件夹版以后：启动只要 1~3 秒，4 个并行进程也能正常共享，不再有临时目录垃圾。

如果确实需要一个单文件 exe（例如要发邮件），把 `build_exe.bat` 里的 `--onedir` 改成 `--onefile`，
但请把「并行进程」设为 1。
